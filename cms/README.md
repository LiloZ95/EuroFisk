# EuroFisk CMS

The admin panel the shop owner uses to change photos, text, menu items and prices — with
no code changes and no developer involved.

Built with [Payload](https://payloadcms.com) (Next.js), a Neon Postgres database, and
Cloudflare R2 for image storage.

## How it fits together

```
  ┌─────────────────────────────┐
  │  cms/  (this folder)        │   Owner logs in here.
  │  Payload admin + REST API   │   Runs on Railway / Fly / any Node host.
  │  Neon Postgres  ·  R2       │
  └──────────────┬──────────────┘
                 │  read at BUILD time only
                 ▼
  ┌─────────────────────────────┐
  │  ../  the public website    │   Static Vite build.
  │  Vite + React               │   GitHub Pages — free, fast, always up.
  └─────────────────────────────┘
```

The public site never calls the CMS at runtime. It fetches the content once during the
build and bakes it into the bundle. That means:

- The site stays fast and free to host.
- If the CMS is down, **the live site is unaffected**.
- Edits go live after a rebuild (~2 minutes), not instantly.

## First-time setup

### 1. Database — Neon

1. Create a free project at [neon.tech](https://neon.tech).
2. Copy the **pooled** connection string.
3. Put it in `.env` as `DATABASE_URI`.

### 2. Image storage — Cloudflare R2

1. Cloudflare dashboard → **R2** → *Create bucket* (e.g. `eurofisk-media`).
2. **Manage R2 API Tokens** → create a token with *Object Read & Write* for that bucket.
3. On the bucket → *Settings* → enable a **Public Development URL**, or bind a custom
   domain such as `media.eurofisk.se` (recommended — the `r2.dev` URL is rate-limited and
   not meant for production traffic).
4. Fill in the `R2_*` values in `.env`.

### 3. Configure and run

```bash
cd cms
cp .env.example .env      # then fill in the values
npm install
npm run dev               # http://localhost:3000/admin
```

The first visit to `/admin` asks you to create the first user. Make that one an **Admin**.

### 4. Load the current website content

This copies everything the site shows today — both shops, all photos, the full menu in
three languages — into the CMS, so the owner starts with a real site instead of blank
fields.

```bash
# from the repo root, only if the site's source files changed since this was generated:
node cms/src/seed/generate.mjs

# then, from cms/:
npm run seed
```

Safe to run more than once: it matches existing records and updates them rather than
creating duplicates.

## Everyday use

The owner logs in at `/admin` and edits:

| Section | What it controls |
|---|---|
| **Locations** | Both shops: address, hours, phone, all photos, and the home-page text |
| **Menu sections** | Menu categories, dishes, prices, per-kilo variants |
| **Photos** | The image library — upload once, use anywhere |
| **Site-wide text** | Navigation, order form, delivery banner, WhatsApp messages |

Languages are switched with the **locale selector in the top right**. Swedish is the
source language; English and Arabic are translations of it.

## Deploying

Any host that runs Node 20+ works. Railway is the least fiddly:

1. New project → *Deploy from GitHub repo* → set the **root directory** to `cms`.
2. Add every variable from `.env.example` under *Variables*.
3. Set `CORS_ORIGINS` to the deployed CMS URL.
4. Deploy. The admin panel is at `https://<your-app>.railway.app/admin`.

Expect roughly **$5/month** for the server. Neon and R2 both have free tiers that this
site's traffic will not exceed.

### Making edits appear on the live site

The public site rebuilds on push. To make a CMS edit trigger a rebuild, add a
[repository_dispatch](https://docs.github.com/actions/using-workflows/events-that-trigger-workflows#repository_dispatch)
webhook — see `docs/CMS-SETUP.md` in the repo root for the exact steps.

## Notes

- `src/seed/data.ts` is generated. Don't hand-edit it; once the CMS is live it's history.
- `src/payload-types.ts` is generated by `npm run generate:types` and is gitignored.
- Changing `PAYLOAD_SECRET` logs everyone out.
